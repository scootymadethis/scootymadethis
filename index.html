Parole difficili, spiegate facile
Minimalità

Vuol dire: non c'è niente di troppo. Se puoi togliere una colonna e funziona ancora, allora non è minimale.

Univoco

Vuol dire: uno solo. Un valore univoco identifica una sola riga.

Istanza

È la situazione attuale dei dati, cioè le righe presenti in questo momento.

02

Tutte le chiavi, in ordine

Il concetto più importante è la minimalità.

Passaggio 1Superchiave

Attributi che identificano univocamente ogni tupla.

Passaggio 2Chiave

Superchiave minimale: non puoi togliere nulla.

Passaggio 3Chiavi candidate

Tutte le chiavi tra cui puoi scegliere.

Passaggio 4Chiave primaria

La candidata scelta. È univoca e NOT NULL.

Con Matricola univoca...
Superchiave{Matricola, Nome}Sì
Chiave{Matricola}Sì
Non basta{Nome, Cognome}No

Mario Rossi compare due volte: Nome + Cognome non identificano la tupla.

Tre cose da non confondere
1
Minimale ≠ un attributo

Una chiave può essere composta da più colonne, tutte necessarie.

2
Le candidate possono essere più di una

Es. Matricola e Codice fiscale, se entrambi univoci.

3
Primaria = una scelta

È la chiave candidata scelta come riferimento principale.

✦
Frase da imparare

Ogni chiave è una superchiave, ma non ogni superchiave è una chiave.

Esempio grafico: perché conta la minimalità?

❌ {Matricola, Nome}

  • Identifica la riga? Sì.
  • Però Nome è di troppo.
  • Quindi è una superchiave, non una chiave.

✅ {Matricola}

  • Identifica la riga? Sì.
  • Puoi togliere qualcosa? No.
  • Quindi è una chiave.

PK = Primary Key · FK = Foreign Key

FK
Chiave esterna

Uno o più attributi che fanno riferimento a una chiave di un'altra tabella (o della stessa).

✓
Integrità referenziale

Ogni valore FK non NULL deve trovare il corrispondente valore nella tabella riferita.

!
Attenzione

La stessa FK può comparire in più ordini. Non deve essere sempre univoca.

Se in CLIENTI esistono solo ID 1 e 2, non puoi inserire un ordine con ClienteID = 99. Un valore NULL è possibile solo se la colonna lo permette.

04

Domini e vincoli

Le regole che i dati devono rispettare.

NOT NULL

Il valore non può essere NULL (assente).

UNIQUE

Non consente valori non NULL duplicati nella colonna o combinazione scelta.

PRIMARY KEY

Chiave primaria: univoca e mai NULL.

FOREIGN KEY

Collega tabelle e controlla i riferimenti.

CHECK

Controlla una condizione, per esempio Voto >= 18.

DEFAULT

Valore usato automaticamente quando non ne fornisci uno.

Esempi grafici: valori accettati o rifiutati
✅ Valido

Voto = 24 con CHECK (Voto >= 18).
Il valore rispetta la regola.

❌ Non valido

Voto = 15 con CHECK (Voto >= 18).
Il DBMS blocca l'inserimento.

✅ Valido

Nome = 'Luca' con NOT NULL.
Il campo non è vuoto.

❌ Non valido

Nome = NULL con NOT NULL.
Il DBMS rifiuta il valore.

D
Dominio

Insieme di valori ammessi: es. INTEGER, VARCHAR(40), DATE.

+
Dominio personalizzato

Un tipo definito a partire da uno esistente, con eventuali CHECK e DEFAULT. Evita di ripetere gli stessi vincoli.

!
Violazione di un vincolo

Una modifica non valida viene rifiutata, salvo le azioni referenziali applicabili.

05

SQL: DDL e DML

SQL significa Structured Query Language.

DDL
Data Definition Language

Modifica la struttura del database (schemi, tabelle, domini, vincoli).

CREATEALTERDROP
DML
Data Manipulation Language

Modifica i dati che sono dentro le tabelle.

INSERTUPDATEDELETE
↗
Come ricordarlo?

DDL = cambia la tabella. DML = cambia ciò che c'è nella tabella. SELECT serve a interrogare i dati (spesso detto DQL).

Schema grafico: quando usare cosa?
DDL

Usalo quando devi costruire o cambiare la tabella.

CREATE · ALTER · DROP
DML

Usalo quando devi inserire, modificare o cancellare righe.

INSERT · UPDATE · DELETE
DQL / SELECT

Usalo quando devi leggere i dati, senza cambiarli.

SELECT
06

Comandi SQL da sapere

Sintassi essenziale. Puoi copiare gli esempi.

CREATE

Crea una tabella o un dominio.

CREATE TABLE ...
ALTER

Modifica la struttura già esistente.

ALTER TABLE ...
DROP

Elimina una tabella o un dominio.

DROP TABLE ...
Creare una tabella
CREATE TABLE CLIENTI (
  ID INTEGER PRIMARY KEY,
  Nome VARCHAR(50) NOT NULL
);
Modificare / eliminare
ALTER TABLE CLIENTI
ADD COLUMN Citta VARCHAR(40);

ALTER TABLE CLIENTI
DROP COLUMN Citta;

DROP TABLE CLIENTI;
Dominio personalizzato (SQL standard)
CREATE DOMAIN VOTO AS INTEGER
DEFAULT 18
CHECK (VALUE BETWEEN 18 AND 30);

DROP DOMAIN VOTO;
Creare una Foreign Key
CREATE TABLE ORDINI (
  ID INTEGER PRIMARY KEY,
  ClienteID INTEGER,
  FOREIGN KEY (ClienteID)
    REFERENCES CLIENTI(ID)
);
Manipolare i dati (DML)
INSERT INTO CLIENTI (ID, Nome)
VALUES (1, 'Mario');

UPDATE CLIENTI
SET Nome = 'Luca'
WHERE ID = 1;

DELETE FROM CLIENTI
WHERE ID = 1;
Leggere i dati
SELECT * FROM CLIENTI;
RESTRICT evita l'eliminazione di oggetti con dipendenze; CASCADE propaga l'eliminazione alle dipendenze. Il supporto esatto dei comandi può cambiare in base al DBMS. Il dizionario dei dati conserva informazioni su tabelle, colonne e vincoli (metadati).
Mini dizionario · parole difficili
DBMS

È il programma che gestisce i database, per esempio MySQL.

NULL

Un valore assente o sconosciuto. Non significa zero.

Vincolo

Una regola che i dati devono rispettare.

Referenziale

Riguarda i collegamenti fra tabelle.

Metadati

Dati che descrivono altri dati, come i nomi delle colonne.

VARCHAR(50)

Un testo di lunghezza variabile, fino a 50 caratteri.

INTEGER

Un numero intero, come 7 oppure −2.

CASCADE

Propaga una modifica o un'eliminazione alle righe collegate.

WHERE

Indica quali righe usare. Senza WHERE, UPDATE e DELETE possono modificare tutte le righe.

07

ON DELETE · ON UPDATE

Che cosa succede ai riferimenti quando cambia una riga collegata?

AzioneSignificato semplice
CASCADEPropaga l'eliminazione o la modifica alle righe collegate.
SET NULLMette NULL nella chiave esterna collegata.
SET DEFAULTAssegna alla chiave esterna il suo valore predefinito.
NO ACTIONSe il riferimento diventerebbe invalido, l'operazione non è consentita.
Queste regole valgono per le Foreign Key. SET NULL richiede una colonna che ammetta NULL; SET DEFAULT richiede un valore predefinito compatibile con i vincoli.
Esempio: aggiungere una FK con una reazione
ALTER TABLE ORDINI
ADD CONSTRAINT fk_cliente
FOREIGN KEY (ClienteID) REFERENCES CLIENTI(ID)
ON DELETE CASCADE
ON UPDATE CASCADE;
